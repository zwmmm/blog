制作过程

听完曲子，很多人会好奇没有乐理基础是怎么做出来的。如果只是把一段词丢给 Suno 盲猜，很容易词曲不搭。我常用的制作流程是：曲子先行 ➔ Cover 锁定 ➔ AI 对话迭代填词。

第 1 步：找曲子（找纯音乐或开盲盒）

  • 找现成伴奏：去网上找一些自己觉得好听的免费纯音乐素材。
  • Suno 风格开盲盒：在 Suno 里尝试不同风格词抽卡，直到随机摇出一段自己满意的旋律或伴奏。

第 2 步：用 Suno 的 Cover 功能锁定旋律

找到中意的曲子后，核心技巧是使用 Suno 的 Cover（翻唱/重构）功能。这样可以在保证曲子旋律和伴奏走向基本不变的前提下，把精力完全放在后续的歌词替换与演唱调整上。

第 3 步：与 AI 对话填词，反复调试词曲融合

  • 明确情境：先给 AI 一个具体的故事背景或情绪冲突（比如深夜机房的焦虑与释怀），避免生成假大空的词。
  • 约束结构与标签：要求 AI 严格按 [Intro], [Verse], [Pre-Chorus], [Chorus], [Bridge], [Outro] 输出，副歌控制在 4 句以内。
  • 卡字数与修韵脚：听着旋律数节拍，要求 AI 把每句话的字数严格限制在固定区间（例如 7 到 9 个字），统一押韵，去掉拗口书面语。
  • 重新填词与试唱：根据 Suno 生成后的实际听感，哪一句唱得别扭就针对性让 AI 换词重写，慢慢磨到词曲自然融合的程度。

3. 自动化每日新闻系统

除了偶尔创作图片和音乐，我还用 AI 搭建了一套全自动的每日新闻流。每天各处刷信息容易过载，不如让 Agent 每天定时按照我的关注偏好和排版规范把前沿动态整理出来：

我的采集源与接口机制

  • 社区热门帖子：通过 Hacker News Algolia API、Linux.do RSS 订阅源与少数派精选 API 采集最新高热讨论。
  • 大模型与学术前沿：通过 Hugging Face Daily Papers API 与 GitHub Trending 获取最新论文与高星开源代码。
  • Apple 生态与小而美软件：跟踪 macOS/iOS 原生开发动态、Swift 社区与独立出海作品。
  • 中文推特热议：定向检索 Claude Code、Cursor、智能体架构与避坑实操等高互动内容。

自动化输出流水线

  • 定时触发：每天早上 9 点由调度任务自动唤醒 Agent 执行。
  • 信源检索与真实落地页清洗：检索 24 小时动态，强制提取具体 GitHub 仓库全路径、官方 Release 或 App Store 落地页，剔除空链接。
  • Kami 排版渲染：按照 Kami 羊皮纸设计系统，直接输出独立的单日静态网页 news/YYYY-MM-DD.html。
  • 双向索引与自动部署：更新 news.html 列表和首页每日新闻板块，自动执行 Git 提交并推送至 GitHub，触发 Vercel 秒级构建上线。
把写代码的工程化和自动化思维用在多模态创作与信息流上，不仅省去了人工维护的繁琐，每天早上醒来还能得到一份排版干净、没有噪音的前沿内参。
