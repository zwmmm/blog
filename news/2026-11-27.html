大模型 AI编程 中推

OpenAI 修正 GPT-6.2 额度计算并补发备用重置，实测指向“成本控制”且原 Claude Code 核心成员加盟

OpenAI Codex 与 ChatGPT 负责人 Thibault Sottiaux 发文确认，GPT-6.2 Astra 与 Sol 上线初期存在计费误差，导致多数请求按低于实际的折扣扣减配额；误差修正后完成同等工作量时，Astra 触及额度上限的速度加快 40%，Sol 加快 25%。OpenAI 表示不会追溯补扣历史差额，并向所有 Go、Plus、Pro 与 Business 账户发放 1 次备用重置作为补偿。Linux.do 社区多个高热讨论帖也反馈收到官方邮件通知，涉及 GPT-6.2 Astra、Sol 及 Ultrafast 模式在内的 Codex 请求已恢复全额计量。针对用户对 6.2 表现不如前代的质疑，独立对战评测平台 Agent Duel 统计真实编程任务发现，相比 GPT-6 与 Sol 6.1，Astra 6.2 和 Sol 6.2 的单任务输出 Token 与推理 Token 均出现统计学显著下降（Sol 推理下降显著性 p=0.00013，Astra p=0.0064），作者判断模型在当前阶段被明显调向成本压缩。与此同时，曾深度参与 Anthropic Claude Code 技能系统与 Agent SDK 建设的工程师 Thariq Shihipar 正式宣布加入 OpenAI，与原 Claude Code 产品负责人 Cat Wu 等人在 Codex 核心团队汇合。

02
智能体 AI编程

Google 明年 2 月强制 AI 智能体接入 Workspace MCP，但公开版 Gmail 暂不支持发信

Google 正式开放 8 个官方 Workspace MCP 服务器并修订 API 服务条款（Workspace AI Tools Addendum）：自 2027 年 2 月 1 日起，任何由 AI 智能体、Harness 或大模型驱动的工具或 CLI 访问 Gmail、Drive、Calendar 等套件时，必须通过官方 MCP 服务器路由，严禁通过非 AI 伪装绕行，否则将面临限流或封禁，且违规直连 REST API 的项目会被强制降级至 Standard 配额。新条款同时规定，基于 Workspace 数据构建的向量嵌入、记忆索引、用户画像与组织图谱最长仅可保留 30 天，且禁止用于模型训练、微调、评估或蒸馏。值得注意的是，当前公开版 Gmail MCP 仅提供搜索、读信、新建草稿与加标签工具，发送、回复、转发以及二次修改既有草稿均标记为仅限合作伙伴（如 Claude 官方连接器）调用；Drive MCP 亦暂缺移动目录与共享权限能力。配额方面，免费 Standard 层每项目每日上限为 5,000 次请求，其中 Gmail 的会话检索与草稿列表单次折算 10 次请求，即全项目用户每日仅共享 500 次搜索，迫使大量依赖直连 REST 搭建记忆型办公智能体的独立开发者重新评估架构与合规边界。

03
Apple AI编程 智能体

原生 macOS 多智能体工作区 Seahelm 开源：基于 Ghostty 并行调度 Claude Code 与 Codex

面向并行 AI 编程工作流的原生 macOS 应用 Seahelm 正式以 MIT 协议开源（同步上线 seahelm.dev）。该项目完全放弃 Electron，采用 Swift 与 AppKit 原生构建（支持 macOS 14.0 及以上系统），终端渲染直连 Ghostty C API（libghostty-vt），并通过独立守护进程 seahelmd 维持会话持久化，即便关闭客户端或重启电脑也能完整恢复终端屏幕与智能体上下文。Seahelm 将 Git worktree 作为核心调度行，同一工作区下可按分屏并行托管 Claude Code、Codex、Cursor、Aider、Gemini、OpenCode 等 12 款 CLI 工具的状态检测；当 Claude Code 在运行中新建 worktree 并切过去干活时，Seahelm 会保留原面板并自动调用会话分叉命令（fork-session）在新 worktree 卡片中接续完整对话上下文。界面交互上，屏幕顶部边缘常驻名为 The Island 的轻量状态胶囊，汇总当前各路智能体的工作态、待审批提醒及 Claude/Codex Token 配额余量；内置规则引擎 First Mate 可监听状态跃迁并在侧边栏生成点击式建议卡片，同时整合文件树、CodeEditSourceEditor 编辑器、Git Diff 审查与 iMessage 远程批准能力，补足了多分支并发编程时“只见终端滚动、难以及时决策”的短板。

AI编程 独立开发

1Password 披露内部系统入侵事件：员工 GitHub 失陷致部分元数据外泄，保险库密钥无恙

密码管理服务商 1Password 发布安全公告，通报其自 11 月 19 日启动调查的一起内部供应链入侵事件，消息同时登上 Hacker News 榜首（超 1,600 赞）与少数派派早报头条。调查确认，攻击者通过控制一名员工的企业 GitHub 账号进入内部代码仓库与 CI/CD 系统，窃取了私有源码并向部分后端服务植入恶意代码，借此下载了部分客户的姓名、电子邮箱、账户与用户 ID、账户创建及最后登录时间、公钥、安全远程密码（SRP）协议参数，以及部分邀请、配置与恢复链接令牌。1Password 强调，基于零知识端到端加密与双密钥派生（2SKD）架构，用户的账户密码和设备本地生成的 128 位 Secret Key 均不上传服务器，SRP 验证过程也不传输上述凭据，因此所有客户保险库密文、密码条目、主密码、Secret Key 及客户端扩展均未受损，也未发现账户被接管的证据。官方现已禁用涉事 GitHub 账号、轮换全部内部凭据，并将账户邀请及恢复邮件中的验证码由 6 位纯数字扩展至 10 位字母数字组合，同时提醒开发团队与用户警惕借此事件名义发起的钓鱼邮件与社工诈骗。

05
智能体 大模型

NVIDIA NeMo 发布模型自治上下文研究：以 Context API 替代被动压缩，32K 预算准确率翻近三倍

NVIDIA NeMo 团队发表论文《Letting Models Manage Their Own Context: Where We Stand》并入选 Hugging Face 每日论文榜，配套实验工作区已在 GitHub 开源（github.com/nvidia-nemo/labs-OO-Agents）。当前主流 Agent 框架多在上下文窗口触顶后被动触发历史摘要压缩，该研究则在 NVIDIA 开源框架 nooa 中向模型开放 Context API，令其自行决定何时裁剪并保留哪些推理片段。团队在 8K 至 512K Token 预算梯度下对文档研究（OfficeQA Pro v2）与机器学习工程任务进行了系统对比，结果显示主动调用 Context API 的模型不仅准确率更高，而且在紧凑预算下耗费更少输入 Token：GPT 6.1 在 32K 预算下的任务得分从 21% 跃升至 56%，Kimi 在保持更高准确率的同时输入 Token 消耗最多降低 41%。实验也揭示不同模型对压缩时机和激进程度存在显著差异，且微调提示词即可改变裁剪节奏；针对模型修改上下文可能破坏前缀缓存的工程瓶颈，作者验证了推理引擎侧“复用未变更后缀 KV Cache”方案，可在精度零损失的前提下削减最高 15% 的单次预填充计算开销。

大模型 AI编程 独立开发

纯 x86-64 汇编实现 Qwen3-0.6B 推理与可启动 OS：llm.asm 仅 12 KB 零依赖登榜 GitHub

由开发者 alesha-pro 开源的硬核工程 llm.asm 仅上线两天便在 GitHub 斩获超 1,500 星标与两百余次 Fork。整个仓库共计 17,252 行纯 x86-64 NASM 汇编代码，完全不依赖 C、C++、Rust、libc、libm 或任何动态链接库，仅凭 nasm 与 ld 即可构建出三个独立可执行系统：约 12 至 14 KB 的静态 Linux ELF 版 Qwen3-0.6B 推理引擎（支持多轮对话与 KV Cache 复用）、约 22 至 24 KB 支持 Multiboot 1 引导与 SMP 多核裸机运行的独立大模型操作系统（可生成 BIOS+UEFI 镜像在 QEMU KVM 或 Proxmox VE 无盘启动），以及 32 KB 自带 Unicode 盲文字符实时损失曲线 TUI 的 Mini-GPT 从头训练器。作者纯手工编写了 AVX2+FMA+F16C 矩阵核、expf 与 sincosf 数学函数、RMSNorm、RoPE、SiLU、BPE 分词器，以及基于 Linux clone 与 futex 系统调用的线程池和 AdamW 优化器。在 AMD EPYC 7642 纯 CPU 同模型（Qwen3-0.6B Q8_0）基准对比中，其自回归解码阶段凭借 INT8 向量乘加与连续头优先 KV 布局，在 1 至 40 线程区间稳定领先 llama.cpp 18% 至 36%，且任意线程数下均保持比特级确定性输出。
