AI编程 智能体

Ricursive Intelligence 正式发布开源前沿模型 Ripple-65B Preview 并在 Hacker News 引发热烈讨论。该模型从零开始在 12 万亿 Token 高质量数据上完成预训练，原生支持 100 万 Token 动态上下文。在考察终端环境探索与真实操作系统操控能力的 TerminalBench 2.1 权威基准测试中，Ripple-65B 取得 80.52 分的高分，位居全球开源权重第一。团队通过自研的“陡峭上升强化学习”（Steep Ascent RL）算法，仅耗费 140 万次轨迹展开（比同类方案少 70 倍），将全流程总研发预算压缩至 3200 万美元（仅为传统前沿模型成本的十分之一），展示了小团队凭借精准强化学习算法在开源代码智能体赛道实现技术突围的全新路径。

AI编程 独立开发

Go 语言官方团队在技术博客正式发表《JSON v2 Specification》，公开了酝酿已久的全新标准库模块 encoding/json/v2 规范与实验性原型。自 Go 1.0 诞生至今十五年来，标准库原有 JSON 实现因过度依赖全局缓存、反射开销大、缺乏流式零分配机制以及错误处理不透明等痛点长期困扰高吞吐后端与智能体数据序列化。全新的 JSON v2 彻底解耦了底层分词解析器与高层序列化逻辑，提供零内存分配的流式编码解码器，支持细粒度自定义 Marshaler 选项，并在保持对经典 API 语义向后兼容的同时，将数据处理吞吐与序列化速度提升数倍，为云原生高并发服务与智能体工具数据流提供了坚实的性能基础。

Hugging Face 每日论文揭示上下文衰减根源：注意力竞争而非单纯长度导致长文本智能体检索失真

大模型 AI编程

针对长文本大模型在实际代码检索与多轮智能体调用中频现的“上下文腐烂”（Context Rot）现象，最新被 Hugging Face 收录的精选论文《Length Is Cheap, Competition Is Not: Attention Predicts Context Rot in Retrieval》（arXiv:2611.04169）通过严谨实验打破了既有认知。研究证实，上下文绝对长度本身并不是性能骤降的主因（填入无关噪音词时，模型在 32k 长度下仍能保持约 99% 的准确率）；真正的致命元凶是存在语义相近的竞争性干扰项，注意力分散指数能解释高达 58% 的性能下降方差。该发现为开发长文本智能体时的检索提示词构建、历史上下文剪枝策略以及代码库分块索引设计提供了极具实操价值的理论指导。
